# google/zx：用 JavaScript 写 shell 脚本的跨平台工具

zx 是 Google 出品的「写脚本更顺手」的工具，仓库描述为 "A tool for writing better scripts"，当前 45,787 star，Apache-2.0 协议，作者 Anton Medvedev。我这次读到的版本是 `package.json` 里标注的 **8.9.0**。

## 它解决什么问题

Bash 写简单脚本顺手，脚本一复杂就难维护；JavaScript 生态成熟，但 Node 标准库的 `child_process` 用起来繁琐。zx 的定位是「两边的好处都要」：在 `child_process` 之上封装出一套跨平台、带合理默认值、自动转义参数的 shell 调用方式（README 原文：*provides useful cross-platform wrappers around child_process, escapes arguments and gives sensible defaults*）。

## 安装与运行

```bash
npm install zx
```

脚本文件开头写 shebang，然后用 `$` 模板标签执行命令：

```js
#!/usr/bin/env zx
await $`cat package.json | grep name`
const branch = await $`git branch --show-current`
const name = 'foo bar'
await $`mkdir /tmp/${name}`   // 参数自动转义，空格无需手动处理
```

兼容性写得很清楚：Node.js >= 12.17.0、Bun >= 1.0.0、Deno 1.x/2.x，跑在 Linux/macOS/Windows 上，支持 CJS/ESM 与 JS/TS。

## 核心 API 与全局

入口 `src/index.ts` 只做「再导出 + 版本」：`export * from './core.ts'`、`export * from './goods.ts'`，并导出 `minimist / dotenv / fs / YAML / glob` 等。`$` 返回一个 `ProcessPromise`，旧的顶层 `nothrow()` / `quiet()` 已在 `src/index.ts` 标为 `@deprecated`，现在改用 `$` 结果链式调用 `.nothrow()` / `.quiet()`。

`src/globals.ts` 通过 `Object.assign(globalThis, _)` 把一批 API 注入全局：`$`、`cd`、`chalk`、`question`、`within`、`sleep`、`retry`、`spinner`、`glob`、`fs`、`YAML`、`dotenv`，以及 Windows 下切换 shell 的 `usePowerShell` / `usePwsh` / `useBash`。不想全局注入也可以 `import { $ } from 'zx'`。

## CLI 与工程实现

`src/cli.ts` 的 `printUsage()` 列了完整选项：`--quiet`、`--verbose`、`--shell`、`--prefix`/`--postfix`、`--prefer-local`、`--cwd`、`--eval/-e`、`--install/-i`、`--registry`、`--repl`、`--env`。脚本来源也多样：本地文件、stdin、http(s) URL，`.md` 文件会先被 `transformMarkdown` 转成脚本再执行。

源码是 TypeScript，构建走 esbuild（`package.json` 的 `build:js`），产出 `build/*.js` + `*.cjs` + `*.d.ts`，`exports` 里 import/require 双通道，`bin` 指向 `build/cli.js`，volta 固定 Node 24.13.1。

## 我的判断

zx 的价值在「低摩擦」：把 shell 的顺手套进 JS 的类型、模块和测试体系里。代价是全局注入式 API，对偏好显式依赖的工程团队需要取舍。README 本身很精简，完整文档在 google.github.io/zx，要彻底理解行为还是得读 `src/core.ts`（约 29KB 的核心实现，含 `Options` 与 `Snapshot` 类型定义）。
