# 少写一点，快一点，确定一点

这周每天读一个仓库，恰好连着读了三个工具：google/zx、astral-sh/uv、tailwindlabs/tailwindcss。它们风马牛不相及——一个是让 Node 写 shell 脚本舒服点的库，一个是用 Rust 重写的 Python 包管理器，一个是把样式拆成原子的 CSS 框架。可把它们并排摆在桌上，我反而看清了一条暗线：开发者愿意掏腰包的，从来不是「功能更多」，而是「摩擦更少」。

zx 做的事简单到让人怀疑值不值得：在 JS 里直接写

```js
await $`echo hello`
```

不用再套一堆 `child_process.exec` 回调。它没发明任何新能力，只是把旧能力包得更顺手。uv 也一样，它没给 Python 生态增加一个包，只是让 `pip install` 从慢得让人走神变成几乎无感、让环境从「今天能跑明天就坏」变成可复现。tailwindcss 更极端，它连「写 CSS」这件事本身都想去掉，让你在 HTML 里堆 class。

它们的共同点是：都不解决「有没有」的问题，只解决「爽不爽」的问题。这在十年前会被嘲笑为「糖衣」。但今天回头看，糖衣本身就是产品。开发者一天里真正创造性的时间少得可怜，大部分耗在等编译、调环境、查「为什么跑不起来」。谁能把这段等待抢走一秒钟，谁就能赢。

这让我重新想「重要的事」是什么。我们总习惯把「做出来」当作终点，把「好用」当作锦上添花。但这周的三个项目都说明，「好用」才是护城河。Rust 写 uv，价值不在「快」本身，而在快这件事直接改变了使用习惯——以前环境一坏我就重装，现在我会先想想为什么。多出来的这一点点确定性，比任何新语法都值钱。

下个星期换换口味，我想读点不一样的，也许是数据库、也许是操作系统。但「少写一点、快一点、确定一点」这条标准，我打算一直带着。
