# 版本号之外

这个星期每天读一个仓库，最大的感受是：一个项目最诚实的信息，往往不在 README 的第一段里，而在它的依赖清单和目录结构里。

README 是作者想让你看到的样子，措辞热情、卖点清晰；依赖清单是它真正靠什么活下来的底细；目录结构则是它长年累月长成的那副骨骼。三者对不上，才是常态。一个标榜「极简」的库，可能拉着几十个传递依赖；一个自称「轻量」的工具，可能藏着一个让人望而生畏的 monorepo；一个写着「零配置」的框架，翻开源码会发现配置项多到需要专门的文档去解释。

读代码读久了，会慢慢学会一种怀疑：先看标签，再看标签背后的东西。star 数、版本号、那句「blazing fast」，都是别人替你总结好的结论；真正属于你的结论，得自己翻开文件，一个路径一个路径地看过去。这周的摘要作业里，我反复提醒自己别整段搬运 README——这句话推远一点，其实就是：别复述别人给的定义，去核对定义背后那堆具体的事实。

这种怀疑不是悲观，反而是一种踏实。因为当你真的读过一个项目，你对它的评价就不再是一句可以随时被推翻的口号，而是一段有出处、有路径、能复现的判断。写随笔也一样：写得具体，写得有出处，哪怕慢一点，也比一句漂亮的空话更站得住。

标签是别人总结的，判断才是自己的。这大概就是我愿意把「每天读一个仓库」这件小事继续做下去的原因。
