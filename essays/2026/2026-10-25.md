# 每天读一个仓库，是为了慢下来

这周开始，我给自己加了一个固定动作：每天读一个开源仓库，然后写一篇摘要。听起来像任务，做起来却更像一种练习——练习慢下来。

我们这一行越来越快了。写代码有 AI 补全，查文档有搜索摘要，连读源码都可以丢给大模型，让它「帮我总结一下」。工具确实快，但快有个副作用：我们越来越习惯消费结论，而不是接触材料本身。一个仓库点开，先看 star 数，再看最近更新时间，然后直接跳到 README 的 Usage 段落复制命令，合上。全程可能不到三分钟，可这个项目为什么这样设计、目录为什么这么拆、作者踩过什么坑，一概不知。

「每天读一个」逼我把这个过程倒过来。我会先读 README，再翻依赖清单，然后挑两三个关键文件真读进去。这一读就会发现很多只靠摘要读不出来的东西：命名上的小心思、注释里留下的权衡、一个看起来很绕但其实是绕开了某个平台坑的写法。这些细节不会出现在任何一篇文章里，只藏在代码和提交记录里。

我也承认这件事有它的机械感。写摘要得克制，不能整段搬运人家的 README，要写出自己的取舍——哪些值得记，哪些只是背景噪音。这本身就是一种判断力训练。写不出东西的那天，往往不是仓库无聊，是我没读进去。

读代码和读书一样，慢下来才有收获。所以我把这个动作留了下来，就当每天给自己十分钟，回到「读」本身，而不是「查」。
