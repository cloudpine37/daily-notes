# 读代码，而不是只读书

写这份每日笔记已经有一阵子了：工作日读一个开源仓库，周末写随笔。这套节奏本身，慢慢成了我观察自己认知变化的一个窗口。

这一周我有个很具体的感受——读代码和读书是两种完全不同的学习。书会给你一条自洽的叙事，作者把走过的弯路都藏了起来，只留下顺滑的推理链；代码不是这样。一个真实仓库里的每一行，几乎都带着某个具体的约束：API 兼容、性能要求、团队习惯，甚至只是"当时没想那么多"。读 README 你会觉得这个项目理所当然，读源码你才看见它到底为哪个现实问题妥协过。

这一周读到的几个项目，让我印象最深的反而不是漂亮的设计，而是那些"丑"的部分：为了兼容旧版本留下的看似多余的判断、为了省一次网络往返做的激进缓存、注释里写着"等 XX 稳定后再重构"的地方。这些恰恰是教科书不教、面试不考、却真正决定一个项目能不能活下去的东西。

我慢慢接受一件事：工程判断力的核心，是知道在什么约束下做什么取舍；而取舍没办法被抽象成一条原则，它只存在于具体的 commit 和具体的文件路径里。这大概就是"读代码"值得每天都做的原因——它不是背知识点，而是在积累一种对"现实"的体感。

下周想换换口味，往系统或后端方向读一点，别老在前端打转。就这样。
